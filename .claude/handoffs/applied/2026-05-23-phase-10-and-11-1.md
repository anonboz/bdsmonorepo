## 2. New invariants discovered

### 2.1 `NotificationsService.dispatch` return shape is contractual

The shape `{ id: string | null; enqueue: () => Promise<void>; muted: boolean }`
is consumed by ~7 callers (bills, payments, payouts, tickets,
service-jobs, webhooks, applications). Widening or narrowing it
silently breaks the existing audit-log paths because callers
destructure these three keys.

- **Code today:** signature in `apps/api/src/notifications/notifications.service.ts`.
- **Why it matters:** the 10.4 rewrite required holding this shape
  exactly while changing the internal logic. Anyone touching
  dispatch needs to keep this fixed.
- **Proposed home:** per-domain note in `apps/api/CLAUDE.md` (the
  notifications section, alongside the existing canonical-patterns
  table). Not the root `CLAUDE.md`.

### 2.2 Sweepers acting on a user's behalf set `actorId = userId`, not null

The 10.6 erasure sweeper passes the user's own id to
`performErasure` (and to the corresponding audit row), not
`null`. The convention: "system" actorId is reserved for actions
no user ever initiated (e.g. a daily payouts release based on
elapsed cooldown). Anything that was user-triggered with a
delay still belongs to that user in the audit timeline.

- **Code today:** `AccountErasureService.executeIfDue`,
  `apps/api/src/account/account-erasure.service.ts`.
- **Why it matters:** ops reads the audit log to reconstruct what
  happened to a given user. `actorId: null` breaks that join.
- **Proposed home:** `apps/api/CLAUDE.md` audit-log conventions
  block.

### 2.3 Email-channel mute must write `failureReason` on the Notification row

When dispatch suppresses the email channel via a
`scope=EMAIL muted=true` preference, the persisted row needs
`failureReason` set (we use `'email channel muted by user preference'`).
Without it, the 10.2 stuck-notifications sweeper picks up the row
75 minutes later, retries 3 times, then finalizes — pure wasted
work.

- **Code today:** `NotificationsService.dispatch` writes
  `failureReason` when `emailMute` is true.
- **Why it matters:** the 10.2 filter is
  `sentAt IS NULL AND failureReason IS NULL`. Either column
  finalizes a row.
- **Proposed home:** notifications-service section of
  `apps/api/CLAUDE.md`.

### 2.4 `PushSubscriptionsService.vapidEnabled` reads `process.env` at call time

Unlike every other env-dependent service (which reads the cached
`env` module from `apps/api/src/env.ts`), this getter checks
`process.env.VAPID_PUBLIC_KEY` directly. The deliberate reason:
the spec for 10.5 includes a test case that flips the env between
runs ("create returns 503 when VAPID keys are not configured").
Reading the cached module would make that test impossible without
heavyweight module mocking.

- **Code today:** `apps/api/src/notifications/push-subscriptions.service.ts:31-36`.
- **Why it matters:** if a future refactor "fixes" this to use
  `env.VAPID_PUBLIC_KEY`, the disabled-keys test will need a
  matching shim. Document the asymmetry so the next person doesn't
  cleanup-trap into removing it.
- **Proposed home:** inline comment is already there; mention in
  `apps/api/CLAUDE.md` env-handling section as the documented
  exception to the "always read env via the cached module" rule.

### 2.5 Per-PWA next-intl wiring must be identical across all four apps

Each PWA carries: `withNextIntl()` in `next.config.ts`,
`i18n.ts` at the project root with `getRequestConfig`, a
`localeMiddleware` call inside the existing `middleware.ts`, and
an async root layout wrapping children in `<I18nProvider>` with
`<html lang={locale}>`. Diverging in any one means server-rendered
translations silently break for that app (the cookie is set, but
messages don't load → next-intl falls back to keys).

- **Code today:** four parallel copies in `apps/{tenant,owner,partner,admin}/`.
- **Why it matters:** the message-extraction work in 11.3/11.4
  trusts this plumbing. A missing wrap in one app means strings
  render as raw keys in production for that role.
- **Proposed home:** `packages/i18n/CLAUDE.md` (already has the
  layout, but should grow a "per-PWA checklist" subsection).

### 2.6 Module-level enum widening requires checking dispatch handlers

The 10.4/10.5 work added `PUSH` to `NotificationPreferenceScope`
and the worker fan-out needed to know about it. The `REJECTED`
addition to `MediaStatus` similarly required the worker. Rule:
any new enum value in `packages/db/prisma/schema.prisma` that
maps to a runtime branch (worker, dispatch, audit-action map)
needs a corresponding update in the consumer. TypeScript catches
the obvious switch-statement misses but not nullable filter
shapes.

- **Code today:** worker `fanOutPush` in
  `apps/api/src/notifications/notifications.worker.ts`.
- **Why it matters:** silent runtime drift, not a compile error.
- **Proposed home:** `packages/db/CLAUDE.md` enum-add checklist
  (next to the "Enums in `packages/shared` mirror Prisma enums"
  rule already there).

## 3. Gotchas hit during the build

### 3.1 `nest start --watch` race on Windows wipes `dist/`

- **Symptom:** e2e harness boots `pnpm --filter @repo/api dev`,
  watches print `Found 0 errors`, then `Cannot find module
'Z:\bdsmonorepo\apps\api\dist\main'`. Repeatable on every run.
- **Root cause:** `nest-cli.json` has `deleteOutDir: true`, so
  watch mode wipes `dist/`. The incremental TS build (driven by
  `tsconfig.build.tsbuildinfo`) sees no source changes and emits
  nothing, but the spawned `node dist/main` runs anyway.
- **Fix:** delete `apps/api/tsconfig.build.tsbuildinfo` before
  starting the watcher (or set `deleteOutDir: false`). For this
  session, we worked around by running the unit-test pipeline
  manually and skipping e2e on local Windows. CI presumably
  doesn't see this because each run is from a clean checkout.
- **gotchas.md candidate:** yes — likely to bite anyone running
  e2e from a warm working tree.

### 3.2 TypeScript heap OOM on `pnpm --filter @repo/tenant typecheck`

- **Symptom:** `FATAL ERROR: NewSpace::EnsureCurrentCapacity
Allocation failed - JavaScript heap out of memory`. First hit
  after wiring sharp into the tenant push UI; recurred after
  wiring next-intl.
- **Root cause:** TS chokes on complex web/push typings + sharp
  - next-intl together. Default heap (~2GB) isn't enough.
- **Fix:** `NODE_OPTIONS=--max-old-space-size=8192` before the
  typecheck command. Works at 8GB; needed to go to 16GB once when
  eslint joined the chain.
- **gotchas.md candidate:** yes — already happens on multiple
  apps once their deps grow.

### 3.3 commitlint blocks every commit when a new package adds a scope

- **Symptom:** commit fails with `scope must be one of [...]` even
  when the message follows conventional-commits.
- **Root cause:** `commitlint.config.cjs`'s `scope-enum` is a
  fixed allowlist. Adding `i18n` to a commit needed adding it to
  the enum first.
- **Fix:** included `commitlint.config.cjs` update in the same
  commit as the new package.
- **gotchas.md candidate:** maybe — it's a one-line fix but easy
  to forget. Worth noting that adding a new workspace package
  almost always requires a commitlint scope update.

### 3.4 Vi.fn `mock.calls` typing collapses to `[][]`

- **Symptom:** `Tuple type '[]' of length '0' has no element at
index '0'` when accessing
  `storage.putObject.mock.calls.map(([arg]) => ...)`.
- **Root cause:** `vi.fn()` without a generic param infers an
  empty-tuple argument list.
- **Fix:** cast to the expected shape:
  `storage.putObject.mock.calls as unknown as { key: string }[][]`.
- **gotchas.md candidate:** maybe — comes up whenever a spec
  inspects mock call args.

### 3.5 next-intl strict types reject `Record<string, unknown>` for messages

- **Symptom:** `Type 'Record<string, unknown>' is not assignable
to type 'AbstractIntlMessages'. 'string' index signatures are
incompatible.`
- **Root cause:** next-intl's `AbstractIntlMessages` is a recursive
  union, not a flat dict.
- **Fix:** import `AbstractIntlMessages` from `next-intl` and use
  it as the message-prop type.
- **gotchas.md candidate:** no — only matters once per package.

### 3.6 Method-shorthand interfaces trigger `unbound-method` lint

- **Symptom:** `expect(processor.stripExif).toHaveBeenCalled()`
  fails lint:
  `@typescript-eslint/unbound-method ... may cause unintentional
scoping of 'this'`.
- **Root cause:** TypeScript's method-shorthand syntax
  (`methodName(): Promise<T>`) is interpreted as `this`-bound,
  so passing the method as a reference (which vitest matchers do)
  triggers the lint.
- **Fix:** switch the interface to property syntax:
  `methodName: (input) => Promise<T>`. This declares the method as
  `this: void`-bound.
- **gotchas.md candidate:** yes — applies any time we ship a
  service-interface stubbable in tests.

### 3.7 Prettier autofix can rewrite `existing && existing.x === null` to `existing?.x === null`

- **Symptom:** Spec test for "re-request after cancel rotates the
  token" passes after autofix, but it's worth eyeballing the
  rewrite.
- **Root cause:** `eslint-plugin-prefer-optional-chain` autofix.
- **Verification:** `null?.x` is `undefined`, and
  `undefined === null` is `false`, so the short-circuit semantics
  are preserved. Just confirm visually after every autofix.
- **gotchas.md candidate:** no — TypeScript catches the cases
  where this would diverge.

## 6. What should NOT be in the docs

- **Per-test stub factories.** Each `*.service.spec.ts` carries
  its own `makePrismaStub` / `makeAuditStub` / `makeMailerStub`
  helpers. They're tightly coupled to the service under test;
  factoring them into a shared `@repo/api-test-helpers` package
  would create a brittle coupling without payoff.
- **Specific `web-push` provider choice (Speedio / Twilio).**
  Phase 11.6 will commit; meanwhile leave the open decision in
  BUILD_PLAN §8.
- **`NODE_OPTIONS=--max-old-space-size=8192` invocations.**
  Workaround for typecheck heap pressure; not a long-term answer.
  Belongs in a contributor README at most, not `CLAUDE.md`.
- **Specific commit-message format details beyond
  "Co-Authored-By: Claude Opus 4.7".** Already covered by the
  conventional-commits docs; no new rule.
- **The `process.env` direct-read exception in
  PushSubscriptionsService.** It's an exception, not a rule; an
  inline comment explains it. Don't promote to a global doc.

## 7. Open questions

- **Should the per-scope notification preferences UI in the three
  PWAs (10.4b polish) be the next slice, or do we keep building
  forward through Phase 11?** The backend supports per-scope
  prefs today; the frontend still ships the single-toggle UX.
  Probably fine to defer until after Phase 11 ships, but worth a
  call.
- **Should `@repo/i18n` re-export `useTranslations` / `getTranslations`
  from next-intl?** Today consumers import them directly from
  `next-intl`. Re-exporting would mean one import path to swap if
  we ever migrate libraries; not re-exporting keeps the package
  smaller. I went with not-re-exporting.
- **Does Phase 11.5's email/push template localization need a
  `User.locale` lookup per dispatch?** Phase 11.2 adds the
  column, but the notification worker currently doesn't fetch
  the user row twice. Either thread locale through dispatch or
  fetch+include in the worker. Open.
- **Admin app's English-only carve-out — permanent or for v1
  only?** The wiring is in place; a future support hire who
  prefers Vietnamese would benefit from a flip. Suggest a
  decision before 11.4 lands.
- **The `nest start --watch` Windows race (gotcha §3.1) — fix
  the nest-cli config (`deleteOutDir: false`) or document the
  workaround?** Config fix is one line; current workaround
  requires every developer to know the trick.
